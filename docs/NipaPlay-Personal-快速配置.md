# NipaPlay Personal 快速配置

## WebDAV 媒体库

1. 在 WebDAV 设置中添加本机可访问的连接；Windows 可使用 CloudDrive2 提供的 WebDAV 地址，Android 填写该设备能访问的地址。
2. 打开媒体库管理，添加云媒体库，选择连接并浏览到要管理的目录。只会索引用户选择的根目录，不会改动云盘原始文件。TMDB-ID 扫描完成后会自动打开本次扫描的“云媒体索引”；之后可从 WebDAV 目录浏览工具栏的“查看云媒体索引”再次打开。
3. 扫描作品也会出现在媒体库顶部的“WebDAV媒体库 → 云媒体库”页签；原版观看历史保留在旁边的“观看记录”页签。配置 WebDAV 连接后媒体库页签会显示，不再依赖已有观看记录。
4. 在「设置 → 实验室」分别控制「本地媒体库刮削模式」和「WebDAV 媒体库刮削模式」开关。每项互不影响：关闭使用 NipaPlay 原版流程，开启使用 TMDB-ID 模式，从目录名识别 TMDB ID；TMDB-ID 扫描只列目录和文件元数据，不读取视频正文。本地扫描后可从「本地 TMDB 媒体库」打开海报墙，即使作品没有 Bangumi 关联也能查看已索引的 TMDB 元数据。
   重扫会先比较目录中的相对文件路径：没有文件增删时直接沿用已有作品资料，不重新刮削；新增文件只更新对应作品，删除文件只更新文件索引。同一 WebDAV 连接下清单相同、名称相同的根路径别名会自动合并，避免重复海报。
   WebDAV 管理的工具栏提供“管理已刮削目录”，Windows 和 Android 都可使用。列表支持按名称、路径或媒体来源搜索，支持全选和多选后批量移除索引；已映射目录仍可单独打开索引、映射到本机目录或重新刮削。
5. 在同一页面切换「动画详情页模式」：关闭为原版布局，开启为分类模式，作品详情页增加正片、特典、CDs 和 Scans 分类。文件归属/分类可在作品文件列表中人工修改并锁定；重扫会保留锁定关系。
   详情页会优先采用同一弹弹play/Bangumi 作品的高清封面；已有的低清弹弹play缩略图会在下次扫描时一次性升级。年份从弹弹play、Bangumi 或 TMDB 资料统一提取；类型标签优先保留一个播出方式、一个制作公司和一个改编来源，再用题材标签补足最多 8 个，年份和月份标签不会重复显示。弹弹play简介末尾自动附加的“AI 辅助翻译”署名会在入库、读取和旧索引修复时统一移除。角色和声优会优先显示 Bangumi 详情资料中的“简体中文名”，只有详情未提供中文名时才回退到原始日文名；中文名按角色或人物 ID 按需获取并缓存。存在 OVA、OAD 或 SP 时详情页会加载 TMDB 特别篇；文件名中的 OVA 与 TMDB 的 OAD 视为同一特别篇家族，先按作品年份区分跨季条目，再根据文件内编号或同类条目稳定顺序建立持久映射。没有年份候选时，无编号特别篇保持未匹配，不再猜测到其他季度；不需要把云盘文件改成 TMDB 的 S0E1 格式。单视频电影没有 TV 集号时会使用作品标题，并从 TMDB 图片接口获取、缓存横版剧照作为缩略图；竖版海报只用于作品详情页封面，不会裁剪进 16:9 视频卡片。电影特典只有找到对应剧照时才显示图片，否则统一显示播放器占位图。
6. 若要抓取 TMDB 电影资料，在「设置 → 实验室 → TMDB 元数据访问令牌」粘贴 TMDB 账户 API 设置中的 Read Access Token。令牌保存于设备安全存储，不会同步；TV 条目优先使用弹弹play映射，未匹配时回退到 TMDB，Movie 直接使用 TMDB。

## 跨设备同步

1. 在同步设置中配置同一个可写 WebDAV 同步目录，并在设备上启用自动同步或手动同步。
2. 先在负责扫描的设备添加并扫描媒体库。其他设备同步后会导入索引和作品关系，不会自动重新扫描媒体目录。
3. 在其他设备的媒体库管理中为导入的媒体库选择本机 WebDAV 连接和对应目录。逻辑媒体来源 ID 与相对路径用于定位资源；连接地址和凭据保存在各设备本机。
4. 文件还不能访问时仍可浏览已同步的目录和作品资料；开始播放或阅读时按提示配置本机来源。

播放进度与作品关联通过现有增量同步传输。修改媒体库后可手动同步，避免等待低频后台同步。

## CDs、CUE 与 Scans

- 音频文件可从作品的 CDs 分类打开，使用 NipaPlay 原播放器的暂停、跳转和队列控制。
- `.cue` 文件显示在 CDs 中；打开后选择曲目，应用读取所需的 CUE 文本并按 `INDEX 01` 跳到曲目起点。CUE 引用的音频必须已在同一索引库中。
- Scans 支持 JPG/JPEG、PNG 和 WebP。阅读器按需读取当前图和相邻页缓存，工具栏切换单页/双页；Windows 支持左右方向键。

## 备份与恢复

在「设置 → 备份与恢复」创建 `.npb` 完整备份，选择包含「媒体库」和「观看历史」；在另一设备选择性恢复相同类别。恢复会合并数据，不会把设备专属连接凭据写入共享媒体库快照。恢复后仍需在本机配置 WebDAV 连接和目录映射。

## 构建发行包

项目要求 Flutter、Android SDK/NDK、Windows Visual Studio C++ 工具链及 Rust 工具链。执行：

```powershell
flutter test --no-pub
flutter analyze
.
scripts\package_personal_release.ps1 -Flutter 'D:\path\to\flutter.bat' -Build
```

Windows 便携 ZIP 和 Android APK 会写入 `release/`。Android 使用本机 `android/key.properties` 与 `.personal-signing/NipaPlayPersonal.jks` 固定签名；二者均被 Git 忽略，密钥应安全离线备份，不要提交到仓库。未配置签名时 Gradle 会退回 debug 签名，不能用于覆盖已安装的个人正式版。

Windows 设置和数据库保存在 `%APPDATA%\com.aimessoft\NipaPlay Personal`，与官方版分开。Android 包名为 `com.clainst.nipaplay.personal`，可与官方版并装。

## 跟进官方稳定版

仓库应保留 `upstream` 指向 AimesSoft 官方仓库、`origin` 指向个人 fork，且已启用 `git rerere`。工作区干净并位于 `personal/stable` 时运行：

```powershell
./scripts/update-upstream.ps1 -Version v1.11.12
```

脚本只创建 `upgrade/<版本>` 分支并合并指定的正式版本标签，不会推送，也不会自动覆盖稳定分支。解决冲突后完成测试、Windows/Android 构建和人工启动检查，再将升级分支合并回 `personal/stable`。
